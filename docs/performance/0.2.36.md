# Staged diff content loading

Baseline: published 0.2.35 (`3e51864`). Candidate: 0.2.36 working tree. Windows x64, Obsidian 1.15.0, Electron 43.8.4, Git 2.50.0.windows.1. Timing recording was enabled in both runs; these are local measurements, not latency guarantees.

## Change

Staged comparisons read HEAD and the current index at the same time rather than waiting for HEAD before starting the index query. Changed, Staged and historical comparisons share the existing bounded immutable-blob reader: at most eight entries and four MiB in total. Each uncached blob is read with a two-MiB output bound, without first starting a separate `cat-file -s` process. HEAD and index lookups remain live; working files and editable-session verification remain live. No persistent Git process or new mutable-index cache is added.

The UI keeps Staged read-only and Changed editable. Comparisons still use HEAD-to-index and index-to-worktree respectively. Sharing the content reader does not mean the two modes perform identical Git queries.

## Initial Staged before/after profile

An isolated repository contained four staged files, opened through trusted sidebar mouse clicks in this order: small Markdown, large nested JSON, small nested JSON, large Markdown. One four-click warm-up cycle was discarded; five measured cycles followed. Both runs used the same fixture sizes, paths, driver, timing recording and Obsidian window. The baseline was the published build; the candidate used the changed reader. Runtime load varied substantially, so do not treat median differences as guaranteed improvements or claim a fixed percentage.

| Fixture | Metric | Baseline median (range), ms | Candidate median (range), ms | Samples/method |
| --- | --- | ---: | ---: | --- |
| Small Markdown, 28 bytes / 3 lines | Click to complete-page DOM | 609.4 (450.8–1338.3) | 284.3 (230.1–330.8) | 5 trusted clicks/build |
| JSON, 1,633,783 bytes / 96,003 lines | Click to complete-page DOM | 605.0 (379.5–1032.3) | 357.5 (263.6–532.6) | 5 trusted clicks/build |
| Small JSON, 26 bytes / 2 lines | Click to complete-page DOM | 403.2 (352.3–767.7) | 303.3 (226.2–447.6) | 5 trusted clicks/build |

| All four fixtures | Git subprocesses per click | 7 | 5 | 20 measured clicks/build |

Raw measurements: [staged-switch-before-after.json](staged-switch-before-after.json). The unchanged staged index was checked after both runs. The first two extra processes removed are blob-size queries; repeated blobs can additionally reuse the existing cache when the four-MiB limit permits.

## 100 Staged + 100 Changed files

The final candidate also used an isolated repository with 200 tracked files: 100 with only staged changes and 100 with only working-file changes. Each group contains the four mixed-size targets above plus 96 small Markdown files under nested paths. Both groups have the same target base contents and sizes. Eight warm-up clicks were discarded. Five measured rounds each clicked the four Staged targets followed by the four Changed targets, for 40 trusted clicks. Timing recording was enabled. No performance tests or builds ran concurrently with this collection.

| Target type | Staged DOM / complete median (range), ms | Changed DOM / complete median (range), ms | Samples |
| --- | --- | --- | --- |
| Small Markdown | 147.9 (145.7–313.7) / 150.4 (148.1–316.4) | 140.9 (120.1–280.1) / 215.0 (177.3–403.5) | 5 per mode |
| Large JSON | 193.5 (179.5–397.0) / 197.3 (182.9–405.7) | 250.1 (171.5–479.4) / 329.5 (247.5–656.8) | 5 per mode |
| Small JSON | 278.1 (235.6–471.0) / 280.6 (237.8–473.8) | 198.8 (126.0–326.4) / 349.9 (201.0–387.1) | 5 per mode |
| Large Markdown | 269.6 (196.0–508.2) / 275.8 (198.9–511.5) | 92.7 (79.9–224.0) / 165.1 (147.2–457.8) | 5 per mode |

Staged used four or five Git calls per target; Changed used two or three, including the post-render editable verification. The modes are not equal in speed, and no mode is consistently faster across these targets. DOM-ready excludes later verification; complete includes navigation and, for Changed, post-render safety verification. Neither timestamp guarantees monitor paint. Large ranges show background/system variation; the numbers should not be used as a strict CI latency threshold.

Reproduce with `node scripts/benchmark-staged-switch.cjs <note_test-CDP-port>` after installing the build in a disposable `note_test` vault. The driver runs [staged-switch-ui.js](../../tests/manual/staged-switch-ui.js), checks trusted input, 100/100 status counts, unchanged index and editor modes, and restores methods/settings/repository after cleanup. Raw final samples: [staged-changed-100-samples.json](staged-changed-100-samples.json).

## Correctness

The shared-reader regression checks unchanged reads, cache reuse across editable and read-only views, fresh staged content after an external add, fresh HEAD after an external commit, unchanged index, binary rejection, the two-MiB bound and cache capacity. Existing exact-two-MiB multibyte, unsafe path, symlink, CRLF/BOM, unborn branch, staged rename, history and draft tests remain required. GUI regression checks include mixed/nested files and near/over-two-MiB fallback. This change does not remove save ordering or external-edit protection.
