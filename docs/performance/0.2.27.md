# Sidebar file selection without rebuilding rows

Baseline: release 0.2.26, commit `2d5f38a`. Candidate: 0.2.27, the commit containing this document. Runtime changes are confined to three changed lines in `src/views/source.js`.

Clicking a file previously changed `selected` and called `render()`. Since `selected` participated in the render snapshot, this removed and recreated the branch label, file tree, icons, buttons and their event listeners. A selection now removes the existing selected-row class and adds it to the clicked row. The selection string still includes the group and full path, so staged and unstaged copies of the same file remain distinct. The snapshot excludes selection, preventing the next identical status render from rebuilding the tree solely because of the earlier click.

Actual status, busy/error state, folder collapse or language changes still use full rendering, which restores the selected row from its group/path. Diff/conflict opening uses the original callbacks. No new cache, dependency, timer, filesystem access or Git query is introduced.

## Environment and reproduction

Windows 10 build 19045, Obsidian 1.15.0, Electron 43.8.4 and embedded Node 24.22.1. Same live independent `note_test` vault, warm DOM/OS/V8 caches, legacy my-git disabled. No builds or other tests ran during timing. Run `scripts/benchmark-sidebar-selection.js` in the Obsidian developer console after installing the baseline's three release assets, then build/install the candidate and run the exact script again. Preserve plugin data.json. Scripts refuse other vault names and dirty/saving sessions.

The script supplies synthetic statuses with 10, 100 and 1,000 modified Markdown files, 20 files per folder. Each size discards one warm-up and measures five batches. Batches alternate clicks on two real row buttons, 10 clicks/batch for 10/100 files and 5 clicks/batch for 1,000 files. Each click forces synchronous layout; tables show batch-average per-click times. `openDiff` is replaced by a recorder to isolate the sidebar. Full fixture rendering, Git/file reading, opening the editor and final paint are excluded. The script counts Git calls during collection and restores original status, methods, selected item and collapsed folders afterward. It makes no Git mutations.

The initial collection showed a larger baseline cost, so both released baseline and candidate were reinstalled and rechecked. All four collections are retained in [0.2.27-sidebar-selection.json](0.2.27-sidebar-selection.json). Both candidate collections were built before the metadata version bump and therefore report 0.2.26, but contain the final three-line runtime change. Measurements are local synthetic sidebar operations, not total file-opening time or startup performance.

## Correctness and limits

84 local automated tests pass, including four source-selection regressions. 21 focused Obsidian UI checks cover staged/unstaged duplicate and special paths, one selected row, row/button identity, focused button preservation, unchanged subsequent rendering, conflict routing, collapse/expand, added/removed files, staging transitions, Git-busy controls and actual A/B file navigation. Real fixture edits update line counts and diff chunks, preserve manual drafts and the staged index, and allow undo of new input after reopening. Clean sessions are released and no runtime errors were captured. See `tests/manual/sidebar-selection-ui.js`.

The first UI script incorrectly expected undo of input made before switching to another file to survive A → B → A. A direct comparison using released 0.2.26 and the candidate confirmed the existing behavior on both: draft text survives, but the editor's undo history from before switching does not. This sidebar change does not fix that independent limitation. The final regression checks undo of new input after reopening without claiming cross-file undo preservation.
