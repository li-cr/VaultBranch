# VaultBranch 0.2.22 background refresh measurements

Baseline: `169634b` / release `0.2.21`. Candidate: the implementation released as tag `0.2.22`. Measurements preceded the version-only manifest update, so both raw records report 0.2.21.

## Change and scope

Automatic sidebar status refreshes now require a visible sidebar leaf in a visible document and an expanded root container. Obsidian's `isShown()` alone still returns true inside a collapsed sidebar, so the root's collapsed flag is checked too. No sidebar, a collapsed sidebar or another selected tab no longer causes a status refresh from ordinary file/focus notifications. The one-second existing interval also skips status polling while hidden. The sidebar's initial onOpen uses the same visibility check.

Workspace resize, active-leaf/layout changes and document visibility changes observe a transition back to visible and refresh current status. The existing interval is a fallback for visibility changes without an event. Pending event refreshes recheck visibility when the debounce fires. Explicit refresh and Git actions keep the existing refresh path.

Editor file/raw/focus synchronization remains independent of sidebar visibility. These reads still use worktreeVersions, which checks Git status for conflict safety. This change does **not** eliminate those necessary queries, pause autosave or cache mutable Git status. Hiding a view does not cancel an already running Git query.

## Environment and method

Local Windows 10 build 19045, Obsidian 1.15.0, Electron 39.8.3, embedded Node 22.22.1 and Git 2.50.0.windows.1. Isolated note_test vault: 6 indexed files, 8 tracked Git files, 6 commits, 4 stashes; only VaultBranch enabled as a community plugin. Git was initialized before collection and caches were warm. No test file or Git write is needed for this benchmark.

Execute `scripts/benchmark-background-refresh.js` in the test vault's Obsidian developer console. It refuses other vault names and dirty/saving editor sessions. For each real sidebar state, it sends a synchronous burst of 20 scheduleRefresh requests, waits through the 650 ms debounce (900 ms collection window), awaits any refresh in flight and counts GitService.run calls. Opening/closing/revealing setup queries are outside collection. Periodic polling is suppressed during collection, and preferences are restored afterward. The inactive-tab case creates a second leaf **in the same sidebar tab group**, selects it, then removes it. An early probe used a separate sidebar split and was corrected before recording the final comparison.

Install the baseline's three release files into the test vault, preserving data.json, and save the result; install/build the candidate and repeat the same script and data. Source tests use a controlled scheduler to assert these boundaries as well. Deterministic operation counts are reported; no latency metric or P95 is claimed, and this is not a five-sample timing benchmark.

## Results

| Scenario and scale | Metric and unit | Before | After | Samples and measurement |
| --- | --- | --- | --- | --- |
| Sidebar closed; 6 indexed files / 6 commits / 4 stashes | Git subprocesses per 20-request burst | 2 | 0 | One real UI burst per build; GitService.run wrapper |
| Sidebar collapsed; same vault | Git subprocesses per 20-request burst | 2 | 0 | Same method |
| Inactive sidebar tab; same vault | Git subprocesses per 20-request burst | 2 | 0 | Same method, native tab group |
| Visible sidebar; same vault | Git subprocesses per 20-request burst | 2 | 2 | Same method |
| Same vault | Index SHA-256 unchanged | true | true | Before/after each full benchmark |

The two commands are `status` and `rev-parse` for stash existence. Visible refresh is retained; hidden notification bursts avoid the pair. The first visible refresh still queries the live repository.

Raw results and environment: [0.2.22-background.json](0.2.22-background.json). These measurements establish fewer unnecessary background processes. Cold-start timing, application startup and the previously reported 800 ms remain unmeasured here. Linux/macOS Obsidian UI was not tested locally.

## Correctness

70 local automated tests passed, including four added refresh regressions for visibility states, pending debounce checks, reveal/poll coalescing, hidden editor sync and explicit refresh. 58 local Obsidian UI assertions passed: 14 background-refresh checks, 17 restored-workspace checks, 14 autosave checks and 13 hidden-JSON checks. They cover collapse/tab polling suppression, live status on reveal, concurrent external changes, manual drafts, undo/editor preservation, index safety and session cleanup. The focused script is `tests/manual/background-refresh-ui.js`; other reproducible workspace checks are documented in tests/manual/README.md.
