# Reduce diff preparation to an index read and a bounded blob read

Baseline: 0.2.31 commit `153eb99`. Candidate: 0.2.32, the commit containing this document. This changes editable worktree snapshots, not startup or readonly history loading.

## Comparison and implementation

Inspected the locally installed Obsidian Git 2.43.0 from https://github.com/Vinzent03/obsidian-git. Its desktop split-view createMergeView calls gitShow for the left document and reads the working file through the vault adapter. The native show method delegates to `git show --textconv <ref>:<path>`. Its unified native view calls a file-scoped `git diff`. These view methods do not perform our full-worktree status scan as a prerequisite to content loading. This is source inspection, not a measured cross-plugin benchmark or an assertion that all their workflows issue one command. We do not enable textconv/external diff drivers.

Previously every editable snapshot queried full `status --untracked-files=all --branch` alongside a path-filtered ls-files, then used separate cat-file size and content processes on a blob miss. A newly displayed editable session also performed another required snapshot verification. This made warm opens use four Git processes and uncached opens six.

Use a fresh `ls-files --stage -z` for the entire index instead of full status plus a path-filtered index query. Parse NUL-separated paths literally; stage numbers detect unresolved conflicts anywhere in the index, including another file. Select the requested stage-zero entry by exact path. Operation markers, realpath/lstat, regular-file/symlink checks, UTF-8/size checks and live worktree/index reads remain. This avoids scanning working files/untracked directories and calculating branch/upstream status for a content read. Sidebar and Git mutation status queries retain their existing behavior.

Check the six operation markers concurrently and preserve their priority; propagate filesystem errors. Expose this as check-repository-operation in timing records. This also removes an uninstrumented chain of six filesystem awaits that could extend past Git completion.

On a miss read the immutable blob once with execFile's stdout maxBuffer capped at 2 MiB. Map a buffer-limit error to the existing size-limit fallback; validate text and retain the same eight-hash/4-MiB LRU cache. Child-process timeout, shell:false, argument arrays and error handling remain. Exactly 2 MiB of multibyte UTF-8 is accepted; larger staged text is rejected even if the working file is small. No library, persistent worker or mutable-state cache is added.

Keep the post-render verification and serialized saves. A warm editable open now uses two Git processes (one initial index read and one verification); an uncached open uses three (add one blob read). An untracked file needs no blob process. A fresh snapshot still refuses active repository operations or conflicts. Reading the full index costs output/parsing proportional to tracked entry count; the existing 12-MiB command output limit fails closed. An integration fixture covers 10,001 index entries. This is a tradeoff for obtaining global conflict state and the selected hash from one process.

## GUI reproduction

Use the disposable note_test vault and install baseline release assets. Run:

```sh
node scripts/benchmark-gui-diff.cjs <CDP-port> off
node scripts/benchmark-gui-diff.cjs <CDP-port> on
node scripts/benchmark-gui-diff.cjs <CDP-port> off sequential cold
```

Repeat with the candidate. The final command clears the plugin blob cache before each click; it does not clear OS disk caches, so it is a blob-cache-miss test, not a cold-machine test. Six cycles alternate small Markdown, large nested JSON, small nested JSON, large Markdown; discard the warm-up cycle and retain five samples per file/run. The driver uses real CDP mouse Input and verifies isTrusted. It includes actual reads, editor construction and final verification, with separate DOM-ready, completion and frame-callback milestones. Frame callbacks are not proof of physical display paint. No profiling/automation sleeps are counted as measured work.

Same Windows 10 build 19045, Obsidian 1.15.0, Electron 43.8.4, embedded Node 24.22.1 and Git 2.50.0.windows.1. Autosave/highlighting off, native folding on, warm app and OS caches. Suppress scheduled sidebar refresh temporarily while retaining actual Git reads. No build/test suite runs during benchmark collections. Restore methods/settings, remove staged fixture entries and trash fixture files afterward.

Fixtures before the two-byte worktree replacement: 29-byte/4-line Markdown, 1,633,783-byte/96,003-line JSON, 31-byte/4-line JSON, 1,284,890-byte/24,001-line Markdown. JSON uses large/deep/json/data.json and small/deep/json/data.json; Markdown filenames also repeat across directories. Raw collections: [0.2.32-gui-timings.json](0.2.32-gui-timings.json). Candidate runs precede metadata-only version bump and report 0.2.31. Timing records retain only the 20 measured sidebar operations.

The reductions support improving content preparation, especially on a blob miss. They do not establish a guarantee below 100 ms. Scheduling varied substantially: logging-on large-file completion includes outliers near 800 ms, and some logging-on medians differ little. Logging remains optional/off by default. Do not infer a universal logger overhead from these sequential collections. We did not benchmark Obsidian Git's GUI, cold OS caches, peak memory or Linux/macOS UI. Independent command startup measurements elsewhere are not mixed into this GUI table.

## Correctness validation

104 local automated tests cover ordinary Git workflows plus the changed snapshot path: exact cold/warm command counts, live disk and index changes, unrelated-file conflicts, active operation blocking with a pending operation check, 10,001 index entries with duplicate basenames/literal brackets, exact and over-2-MiB UTF-8 blobs, binary/invalid encoding and symlink/path rejection. Existing tests cover drafts, saves and external-change races.

The note_test loading checks cover large/small alternating and rapid requests, complete-page display, near/over size limits, manual drafts, new-input undo, external change protection, readonly index comparisons and close/cancel cleanup. Timing UI validates operation/index spans without git:status, editor/final verification, copy/clear and optional retention. Startup/restore checks retain manual drafts. No cross-file undo-history change is claimed.
