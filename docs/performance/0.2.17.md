# 0.2.17 历史加载评测

基线源码：`cfe61fe`（`0.2.16`）。优化源码：标签 `0.2.17`，使用 `git rev-parse 0.2.17` 获取对应提交。本次只针对历史重复加载和无变化重绘，不代表整体应用或首次打开的提速。

## 环境与方法

- Windows 10，10.0.19045；命令行 Node.js 24.21.0，Git 2.50.0.windows.1。
- UI 使用隔离 `note_test` 库，Obsidian 1.12.7、Electron 39.8.3、内置 Node.js 22.22.1。基线 UI 安装为 0.2.15，其运行代码与 0.2.16 一致（0.2.16 只改文档和版本）。
- 前后使用相同脚本、数据规模和环境；各预热一次，再重复 5 次。后台自动刷新在 UI 场景中暂停并于结束恢复。系统负载没有锁定，耗时仅作本机参考；调用次数和 DOM 变化为主要验证指标。
- Git 场景由脚本建立临时仓库：1,000 条提交、3 条 Stash，无网络。测量包括 Git 查询、读取 HEAD、解析和分支图计算，不包括 DOM 和绘制。
- UI 场景使用相同的 1,000 条合成提交，前后均替换 Git 查询以单独测量界面。统计 `render()` 返回和同步布局的耗时，以及内容区域 `childList` MutationRecord 数量；不把它当作像素绘制完成或完整文件刷新时间。

| --- | --- | --- | --- | --- |
| 1,000 提交、3 Stash，重复读取相同历史页 | Git 子进程数/次 | 5 | 2 | 各 5 次，拦截 GitService.run 计数 |

Git 耗时原始样本（ms）：优化前 `246.96, 238.68, 262.52, 226.97, 282.44`；优化后 `122.43, 117.55, 112.72, 152.52, 189.93`。

UI 耗时原始样本（ms）：优化前 `452.2, 496.1, 428, 482.2, 432.5`；优化后在最终 0.2.17 构建中为 `0.4, 1.6, 1.4, 2.5, 0.7`。UI 数字只说明跳过未变化的构建工作；真实刷新仍需读取 Git 状态。

## 复现

在源码目录执行 `node scripts/benchmark-history.cjs`。脚本自行创建、清理临时仓库，输出环境、全部样本、Git 命令和中位数，不使用个人仓库。

复测基线时，将 `git show 0.2.16:src/git.js` 与 `git show 0.2.16:src/i18n.js` 的原始输出分别写入同一临时目录的 `git.js` 和 `i18n.js`，然后执行 `node scripts/benchmark-history.cjs /absolute/path/to/baseline/git.js`。两次运行使用当前版本同一份评测脚本。

UI 评测：在隔离 `note_test` 库中分别安装基线和优化版本。通过 Obsidian CLI eval 或开发者控制台，使用 `eval(await require("node:fs/promises").readFile("/absolute/path/to/scripts/benchmark-history-view.js", "utf8"))` 执行相同脚本；记录返回值。脚本只创建临时历史视图，恢复替换的查询并关闭视图。不要在个人库执行。

## 正确性与边界

- 自动测试覆盖每次检查引用和 HEAD、同一提交上的分支切换、分离 HEAD、标签与远程引用变化、删除旧 Stash 而顶部哈希不变、分页/筛选变化，以及手动刷新绕过缓存。
- UI 验证无变化刷新保留 DOM 后仍可点击提交加载文件详情、外部分支变化更新筛选项、手动刷新生效；旧的编辑、隐藏 JSON、外部修改保护和暂存区保护执行回归检查。
- 缓存仅保留一页；每次重读全部引用、HEAD 和 Stash 列表，不缓存工作区状态。未被引用变化反映的特殊 Git 元数据调整，可用界面的手动刷新强制重读。
- 未测：首次打开性能、完整刷新至绘制完成耗时、内存峰值、Linux/macOS Obsidian UI。不对这些项目作性能结论，也不以本机毫秒值作为 CI 硬阈值。
