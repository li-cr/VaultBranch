## Change and scope

The plugin retains lifecycle, settings and public entry points. plugin-events.js owns host event/command/timer registrations; navigation.js owns view opening, request ordering and return-to-graph navigation; git-operations.js owns refresh and save-before-Git coordination. GitService retains subprocess execution, path/status validation and version reads. git-history.js, git-stash.js and git-conflicts.js own the corresponding workflows and share git-limits.js. Explicit plugin/service arguments keep the current settings, service, draft ownership and test overrides effective. No framework or dependency was added. Public methods remain small delegates.

main.js changed from 581 to 297 lines; git.js from 696 to 458 lines. These counts describe responsibilities being separated, not reduced runtime work. Moved method bodies match 1.0.3 after normalizing receiver names and indentation. Git commands, path/index/conflict checks, caches and editor algorithms were preserved. This release makes no speedup or 50 ms switching claim. Full application cold startup, physical paint and memory changes were not measured.

## Environment and method

Windows 10.0.19045; Obsidian 1.15.0, Electron 43.8.4, embedded Node v24.22.1, git version 2.50.0.windows.1. Synthetic data, only in note_test. Both builds are measured sequentially in one release-check invocation after automated tests and build; benchmarks do not overlap them. Other Git plugin work is paused.

Startup uses one warm-up plus five measured plugin reloads, warm OS/V8 caches, openOnStartup=false and closed plugin leaves. This is not a whole-application cold start. Scale and per-call Git attribution are in the raw JSON. loadPluginMs includes script evaluation, lifecycle and CSS; onloadMs instruments the host load lifecycle/settings read within that load. First sidebar and first diff include Git/file reads and synchronous layout, and are timed separately from loading.

Switching uses 100 Staged-only and 100 Changed-only files, alternating small Markdown, large nested JSON, small nested JSON and large Markdown, with duplicate basenames. There are 48 trusted native GUI clicks, eight warm-ups and 20 retained per area. CPU sampling and timing logging are on for both builds; their overhead is included. Highlighting/autosave are off; both builds restore the same folding setting. DOM-ready means the target title, content and controls are committed together; completion also includes Changed verification. Input delay, queue and following-frame callbacks remain separate in raw records. Frames do not establish physical paint.

Editing uses trusted native char/Enter/Backspace events: one warm-up and five measured rounds per file/operation (60 samples per build). CPU sampling, timing logging, highlighting, folding and autosave are off. Input-to-document, synchronous dispatch, delivery and following frames are separate. Document restoration and saving are outside input timers; save/undo/draft correctness is checked separately. Missing frames remain null.

The initial candidate JSON-newline median was 14.7 ms; it was 4.7 ms in the reverse-order batch. That specific initial result did not reproduce. Earlier candidate first-diff batches were slower; a later navigationSetup batch reversed direction (224.6 ms baseline, 216.2 ms candidate). First-diff Git-call spans and residual time are available per startup sample; elapsed subprocess spans include process startup and system scheduling, not just Git CPU. These observations do not establish a consistent speedup or regression caused by the module extraction.

An initial CLI attempt rejected eval before benchmarks began. The first complete UI run passed its assertions but emitted ENOENT diagnostics for already-cleaned synthetic fixtures, so the unified command failed. A traced rerun identified Obsidian MetadataCache.computeFileMetadataAsync reading files after test cleanup; its stacks are retained in raw samples. Waiting for indexing exposed a further cleanup timeout: the oversized Markdown fixture contained one 150,000-line paragraph and kept the host parser busy. The correctness fixture now uses normal paragraphs for the >1 MB Markdown case and multiline JSON for the >2 MB fallback case. The switching and native-input benchmark datasets are unchanged. The final runner waits for the host metadata queue before trashing fixtures and rejects captured console errors. These are test-isolation fixes, with no plugin-runtime behavior change. Measurements from the incomplete traced/cleanup-wait runs remain in raw samples and the table above.

The navigationSetup run subsequently stopped during navigation fixture setup/cleanup. Its cleanup now tracks successful staging, and the test pauses its automatic refreshes during setup. A focused startup-and-navigation rerun passed before the final complete invocation. Its earlier performance samples are retained too; it is not counted as a successful full release check.
