# Latest-click navigation and configurable timing retention

Baseline: release 0.2.29, commit `692d078`. Candidate: 0.2.30, the commit containing this document.

## Implementation

Previously B queued behind all of A's native open, including read, editor construction and post-render verification. Native WorkspaceLeaf.setViewState ignores another call while working; simply removing the queue would lose clicks. Share native view creation only, then call the existing DiffView state handler directly. Its request IDs discard obsolete reads; release late sessions, update/save the current header/layout and reveal only the current request. A clean session no longer queues an empty autosave behind synchronization. Dirty/saving sessions still go through autosave before switching; saves remain serialized per path. Live Git/path/index/worktree checks, final synchronization, atomic page construction and drafts remain. Obsolete Git reads can finish in the background; no subprocesses are killed.

Timing record limit under Other defaults to 100; 0 means unlimited during this run. Apply on Enter or leaving the field, so typing the first digit of 250 does not trim to two. Reducing the limit removes oldest records; increasing it cannot restore them. Invalid/empty input leaves the saved value intact. Logging stays off by default. Records stay in memory, clear when disabled/reloaded and contain no file bodies. Unlimited retention consumes increasing memory. No per-click preference writes or new runtime dependency are introduced.

## Reproduction and environment

Install the baseline's three release assets into a disposable note_test vault and run:

```sh
node scripts/benchmark-gui-diff.cjs <test-CDP-port> on rapid
node scripts/benchmark-gui-diff.cjs <test-CDP-port> off rapid
node scripts/benchmark-gui-diff.cjs <test-CDP-port> off
```

Install the candidate and repeat. The driver uses real CDP Input mouse events and verifies isTrusted. Rapid mode clicks large JSON A then small Markdown B without awaiting A, waits for both, then does large Markdown A to small JSON B. Actual click delivery gaps vary with CDP/renderer scheduling and are recorded as gapMs; they are not fixed production delays. It validates that the last requested file is completely interactive. Sequential mode alternates small Markdown, large JSON, small JSON, large Markdown and waits for each completion.

Discard one warm-up cycle and measure five clicks per file/build/mode: 20 measured clicks per collection. Warm app/OS caches; autosave/highlighting off, native folding on. Automatic sidebar refresh scheduling is temporarily suppressed. Actual Git/disk reads, editors, synchronization and frames remain. No builds/automated tests run during collection. Restore settings/methods, remove staged fixture entries and trash fixture files afterward.

Environment: Windows 10 build 19045, Obsidian 1.15.0, Electron 43.8.4, embedded Node 24.22.1, Git 2.50.0.windows.1. Fixtures before the two-byte working-copy replacement: 29-byte/4-line Markdown; 1,633,783-byte/96,003-line JSON; 31-byte/4-line JSON; 1,284,890-byte/24,001-line Markdown. Other collections show variation/development rechecks; early candidate collections precede metadata/focus-order adjustments. Queue delay falls by removing the preceding navigation from B's dependencies. B still needs its own reads/editor, and obsolete reads can compete for CPU/disk. Logging-on candidate DOM medians were about 13-20 ms above the logging-off collection; this includes scheduling variation, not a universal logger cost. Keep logging off for normal use.

Ordinary sequential switching has no consistent speedup here. Small Markdown baseline DOM medians varied from 119.1 to 170.5 ms between two collections; final candidate was 125.2 ms. Small JSON baseline varied from 104.6 to 180.7 ms; candidate was 135.3 ms. Ranges include substantial outliers. Evidence supports rapid-click queue improvement, not a promise that every switch is faster or below 100 ms. Cold cache, peak memory, Linux/macOS UI and fixed-interval input latency were not measured. Frame callbacks do not guarantee physical paint. Completion includes final verification; DOM readiness does not. Timings are not CI thresholds.
