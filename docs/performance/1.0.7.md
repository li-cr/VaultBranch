# VaultBranch 1.0.7: unused translation cleanup

Version/tag: [1.0.7](https://github.com/li-cr/VaultBranch/tree/1.0.7). Baseline: [1.0.6 / d35c759afa99e704c37aa9c717a06d6e6a3d315d](https://github.com/li-cr/VaultBranch/tree/1.0.6). Tested source: [886964eb231528942483746f307b3f7e9ac46456](https://github.com/li-cr/VaultBranch/commit/886964eb231528942483746f307b3f7e9ac46456). ## Scope and evidence

Remove 13 obsolete English translation entries left by retired source/preview text buttons, loading placeholders and draft dialogs. Espree AST inspection checks literals and tagged-template translation keys, including dynamic label tables; no removed key occurs in current source or tests. ESLint reports no unused local declarations/imports. Public Obsidian hooks, dynamic callbacks, data exported for diagnostics, security checks and fallback paths remain in place. All 292 retained dictionary entries are byte-for-byte equal in value; the translation functions are unchanged. The dictionary has 305 → 292 entries, removing 809 UTF-8 source bytes. Built main.js has 410474 → 409268 bytes. This is maintenance/size cleanup, with no user-visible speedup claim.

All runtime source files except src/i18n.js match 1.0.6 hashes. Git read/write, validation, caching, editor lifecycle, table compatibility and CSS have no changes. No dependency was added; AST/lint tools were used from the local npm cache. Four version files carry 1.0.7. All three baseline assets match official GitHub 1.0.6 release digests.

## Environment and methods

platform: win32 10.0.19045; node: v24.22.1; electron: 43.8.4; git: git version 2.50.0.windows.1; obsidian: 1.15.0; installer: 1.15.0; plugin: 1.0.7. Synthetic note_test fixtures only; source hashes, build hashes and all retained raw samples are linked above. Baseline and candidate execute sequentially in one complete release-check invocation.

Startup: one warm-up and five retained plugin reloads with warm OS/V8 caches, plugin views closed and openOnStartup=false. loadPluginMs includes script evaluation, host lifecycle/settings and CSS; onloadMs is the host load lifecycle portion. First sidebar and first diff are measured separately and include reads/editor setup. Full-application cold startup and physical paint are not measured.

Switching: 100 Staged and 100 Changed files; small Markdown → large nested JSON → small nested JSON → large Markdown, including duplicate basenames and at least three directory levels. Each build uses 48 trusted native clicks: eight warm-ups and 20 retained per area. CPU sampling and timing logging are on; autosave, syntax highlighting and table compatibility are off. domReadyMs requires target title, body and controls together; completedMs additionally includes Changed verification. Input delay, queue and frame callbacks remain separate in the raw samples. Frame callbacks do not establish physical paint.

Changed editing: one warm-up and five retained rounds per fixture/operation, 60 trusted native character/Enter/Backspace samples per build. CPU sampling, logging, highlighting, autosave, table compatibility and folding are off. Native event-to-document latency and synchronous dispatch are separate; save/restore is outside the timer. Fixture index, drafts and undo are checked. Enabled/disabled table rendering remains covered by the table UI regression; its raw measurements are also retained.

## Follow-up of first-use and editing variability

The primary run has higher candidate first-diff time (182.6 → 240.7 ms) and large-Markdown Backspace time (3.7 → 14.1 ms). Those observations triggered one additional startup/editing probe with installation order reversed: candidate first, baseline second. The same build files, synthetic fixture scripts and five retained samples per case were used, with CPU sampling off. The complete primary measurements above remain unchanged; all additional samples are in reverseOrderProbe in the raw report.

| onloadMs | 1.0 [0.8–4.8] | 0.9 [0.8–1.1] | 5 |

| Large Markdown / newline, event → document | 3.7 [3.6–15.5] | 3.7 [3.5–12.2] | 5 |
| Large Markdown / delete, event → document | 8.3 [3.6–15.7] | 3.7 [3.6–12.4] | 5 |

Candidate large-Markdown Backspace is 3.7 ms in the reverse probe versus baseline 8.3 ms; first diff is 261.0 ms versus baseline 291.0 ms. The original candidate-specific increases do not repeat in that order. Editing and Git implementation hashes match the baseline; no candidate-specific slowdown is established by these two batches, and no speedup is claimed. The observed variability is retained as a measurement limitation; it does not prove the absence of overhead. To reproduce this follow-up, install the candidate and run scripts/benchmark-startup.js, tests/manual/staged-switch-ui.js and tests/manual/edit-latency-ui.js; repeat with official 1.0.6, then restore the candidate.
