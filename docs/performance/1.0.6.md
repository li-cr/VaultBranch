## Behavior and bug fix

Other → Tables without a blank line is off by default. When enabled, top-level tables immediately following paragraph text render in note Reading view and Live Preview. MarkdownRenderer supplies the native table rendering, including alignment, inline formatting and links. Live Preview exposes Markdown source while the cursor or selection is in the table, then restores the preview on exit. Reading mode, Source mode, multiple open views and setting changes never insert blank lines or reformat the file. The switch is saved across plugin reloads.

**Bug fix:** exposed source previously looked like ordinary paragraph text, with a different font and size from a native table. Source mode and Live Preview source now reuse Obsidian's HyperMD-table-row and cm-hmd-table-sep classes. Font, size, weight, whitespace and separator color come from the host/theme; no font values or computed-style snapshots are stored. Existing inline Markdown highlighting remains owned by the host. Extra source decorations cover visible lines only. The real UI check compares computed styles with a standard native table.

This does not replace Obsidian's global Markdown grammar or native table grid editor. Support is limited to unindented top-level paragraph/table pairs; existing standard tables, code blocks, frontmatter, comments, math, raw HTML, lists and quotes remain native. Disabling or unloading removes the additional rendering. Independent table-support.js manages registration and setting changes, loose-tables.js handles recognition/Reading view, and table-editor.js handles Live Preview/source. Disabled startup registers neither an editor extension nor a Markdown postprocessor (asserted); the latter would otherwise notify existing Reading views to refresh. Parser/editor modules load only when the feature is used. Ordinary typing rescans the affected paragraph; edits to structural markers can require a full scan. No new dependency was added; Git read/cache paths are unchanged.

## Table compatibility cost

Five samples after one warm-up, CPU sampling and timing logging off. Reading processor includes native fragment rendering, excluding whole-page layout/paint. Field initialization directly measures compatibility scanning/decorations for a 1,120,096-byte note, excluding native editor creation/render. Native typing uses that same note, with focus and composition checked; synchronous dispatch is recorded separately. Zero readings mean below timer resolution, not zero cost. Structural-marker edits and first full-page rendering are not separately timed.

| Probe / metric | Off | On | Samples per setting |
| --- | --- | --- | --- |
| Reading processor / ms | 0.0 [0.0–0.0] | 2.7 [1.0–3.9] | 5 |
| Large-note compatibility field initialization / ms | 0.0 [0.0–0.0] | 9.1 [6.9–15.6] | 5 |
| Live Preview native input / inputToDocumentMs | 46.7 [38.1–65.8] | 45.0 [42.2–55.1] | 5 |
| Live Preview native input / synchronousDispatchMs | 30.1 [26.3–32.5] | 28.9 [26.5–32.9] | 5 |

The disabled processor performs no source lookup (asserted), with measurements below timer resolution. The first scanner implementation at [21160ee](https://github.com/li-cr/VaultBranch/commit/21160ee25f346e6cc6a41669dbb7a463d9e3b68a) took 25.9 [24.9–31.2] ms for the same field-initialization probe. Avoiding per-character backtick scans of ordinary prose and repeated fence-regexp creation reduces that probe to 9.1 [6.9–15.6] ms in the final build. Correctness checks still cover escaped pipes, fences, comments, source ranges and incremental edits. This is a scanner-specific comparison, not a whole-page speedup. Ordinary-input samples do not establish an overall typing speedup. Enabling the feature has a measurable initial scan/render cost.

## Validation and reproduction

129 automated tests and 415 UI assertions pass in the final complete run, including 49 table-specific checks. Trusted clicking/typing, source styles, switch persistence, unchanged standard tables/code blocks, draft/undo preservation, source editing, multiple views, >1 MB notes, cleanup and index preservation are covered. Final retained sessions, pending reads, runtime errors and captured console errors: zero.

An earlier full-suite attempt stopped in the official 1.0.5 baseline input probe with Native editing timeout: delete. Its cause was not established; the entire incomplete attempt is excluded from the comparison, and preceding raw probes remain under incompleteBatch. The runner now retains event/focus/composition/selection diagnostics if a timeout recurs. A subsequent attempt completed all probes and UI cases but failed its final console check: six native saveHistory errors came through a core command checkCallback closing existing deferred Markdown tabs. No suite script invokes a close-tabs command; that whole batch remains under hostCloseTabsBatch and is excluded. Another complete run passed but showed higher candidate onload time; its earlier implementation still registered both table hooks when disabled. It remains under beforeLazyRegistration, followed by the final code change to register only on enable. Final startup samples explicitly assert disabled compatibility and zero table editor extensions. The final isolated complete run has no captured errors. No production error was suppressed, no automatic retry of an executed UI test, no fastest-sample selection.
