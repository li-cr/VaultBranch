# Complete diff pages without an intermediate loading layout

Baseline: release 0.2.27, commit `fbbbebf`. Candidate: 0.2.28, the commit containing this document. Changes concern the diff page; the sidebar selection optimization remains in place.

Previously, file navigation destroyed the current editor and rendered a path, a partial toolbar and “Loading diff…” before starting asynchronous Git/session reads. Save/navigation buttons, captions and the editor arrived later. This exposed an incomplete page and changed the header height. The candidate prepares the comparison before rebuilding the page. The header, controls, captions and content are constructed in a single synchronous task, without a loading-placeholder page between them.

During pending reads, the existing content is inert and marked `aria-busy`, preventing user interaction with controls belonging to the previous file. Background renders cannot supersede an active navigation. Cancellation releases late session acquisitions. The displayed session retains its original release path even after the requested path changes. The new editor is created only after the old editor is destroyed. Git reads, synchronization, manual/automatic save policy, size-limit fallback and external-change safety checks remain enabled. There is no new dependency, runtime timer or mutable-file cache.

## Reproduction and environment

Run `scripts/benchmark-diff-switch.js` in the developer console of an independent disposable Obsidian vault named `note_test`. Install the baseline release assets and run the script; install the candidate and run the exact same script again. No builds or other tests run during collection. All four raw collections are retained in [0.2.28-diff-switch.json](0.2.28-diff-switch.json); candidate measurements precede the metadata bump and therefore report version 0.2.27.

Local Windows 10 build 19045, Obsidian 1.15.0, Electron 43.8.4, embedded Node 24.22.1, Git 2.50.0.windows.1. Same live test instance and warm application/OS caches. The script disables autosave/highlighting, enables native unchanged folding, and suppresses sidebar refresh scheduling during collection while retaining actual Git reads and editor synchronization. It restores settings/methods/folder state afterward, removes its own index entries and trashes its fixture folder.

The script stages and modifies four real files, preserving distinct basenames in different directories. Fixture sizes below describe the original staged contents; replacement of `value` with `changed` adds two working-copy bytes. The order is small Markdown → large JSON → small JSON → large Markdown. Discard one warm-up cycle, then collect five cycles: 20 measured clicks per build. Every click uses the real sidebar handler, Git/session reads and editor creation. This is separate from the synthetic sidebar-only benchmark in 0.2.27.

MutationObserver records intermediate DOM states; animation-frame callbacks sample absence of the editor and the loading placeholder. Header heights are read from layout. Observations show intermediate-page exposure, not physical monitor frames; a zero sampled count is supported by the separate DOM checks, not a guarantee about every platform's compositor. Each timing entry is median (min–max) milliseconds over five opens per build/file.

The repeatable result is elimination of the intermediate partial layout. Timings vary substantially between collections: the initial candidate was slower for two fixtures while the recheck was faster for all four. No file-opening speedup or overall performance improvement is claimed. Cold start, physical paint latency, peak memory and Linux/macOS Obsidian UI were not measured locally. Do not use these timings as CI thresholds.

## Correctness

`tests/manual/diff-loading-ui.js` passes 38 assertions covering complete first-open presentation, pending interaction/refresh behavior, the mixed-size/nested fixtures, rapid requests, errors and close-during-load cleanup. Additional fixtures are a 2,028,909-byte / 34,005-line JSON within the editable limit and a 2,250,000-byte / 150,001-line Markdown file that correctly falls back to a patch preview. Tests cover live line updates, manual draft retention, undo of new input after reopening, manual saving, readonly staged comparisons, external edits, unchanged index and zero runtime errors.

All 89 local automated tests pass. Five new regressions cover deferred complete rendering, background renders, correct release paths, cancelled acquisitions, load-error recovery and uneditable fallback. Another 17 startup/restore UI assertions and 21 existing sidebar-selection UI assertions pass on the final build, for 76 focused Obsidian UI assertions in total. Syntax/version/CSS checks and the build pass. Cross-file undo history from a destroyed editor remains the existing limitation; this change does not claim to preserve it.
