# File History Git Graph

## Changes

File history now displays commit nodes and ancestry lines alongside commit messages. The line projection compresses commits that do not change the selected file. The selected comparison is unchanged: it reads the commit's actual first parent and remains read-only.

The current-branch log is already a single ancestry chain. When the visible page has no merge commit, the graph projects skipped unrelated commits directly onto the next displayed file change. This needs no extra Git process. All-branch history, or a current-branch page containing a merge, needs actual parent rewriting through commits hidden by path filtering; this uses one batched `rev-list`, not one process per visible row. Clicking another already-loaded commit does not rerun file history or rebuild graph nodes; it updates only the old and new selection rows.

## Measurement

The benchmark compares graph data preparation on/off using five alternating samples after one warm-up per mode. It uses a synthetic 50-row page and isolates the data read, including Git subprocesses; it does not measure Obsidian DOM rendering or physical paint.

| Repository history | Graph off median/range | Graph on median/range | Git commands (off/on) |
| --- | ---: | ---: | --- |
| 1,000 consecutive file revisions | 117.61 ms (111.62–118.21) | 119.98 ms (107.36–127.36) | `rev-parse`, `log` / `rev-parse`, `log` |
| 1,000 file revisions interleaved with 1,000 unrelated commits | 118.78 ms (113.22–128.20) | 120.51 ms (113.37–121.34) | `rev-parse`, `log` / `rev-parse`, `log` |

The small differences are within observed run-to-run variation; they are not a latency improvement claim. Both current-branch cases use the same Git process count with graph on and off. The interleaved case also verifies that hidden unrelated commits do not require a repository-wide topology scan.

For repeatable local data, run `node scripts/benchmark-file-history-graph.cjs` on the target build, with no concurrent tests or builds. The script prints environment, each sample, durations and Git commands, and deletes its temporary repository. Raw results: [file-history-graph-samples.json](file-history-graph-samples.json). Environment: Windows x64, Git 2.50.0.windows.1, Node v24.21.0. Results depend on machine, Git configuration, filesystem state and commit graph shape.

## UI Verification

On the isolated `note_test` Obsidian vault, the file-history UI test passed 32 checks including visible graph nodes, stable 68px rows, fork lanes, pagination, renames, read-only comparisons, index preservation, and exactly two row attribute changes per selection. A synthetic branching-and-merge screenshot confirmed fork and merge connectors visually. Twelve trusted mouse clicks alternating small/large JSON history exposed no partial or mismatched detail. The gated stability suite also passed all 36 checks. These are functional/stability results, not total navigation latency measurements.
