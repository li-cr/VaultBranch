# Stable editor UI updates

Baseline: `ff2cc0a` / `1.0.0`. Candidate: tag `1.0.1`; source hashes and synthetic samples are in `1.0.1-samples.json`.

The editable diff used to rewrite captions, pane accessible names, navigation tooltips, save availability and warning visibility on every session notification. The candidate updates static labels when the language changes and writes dynamic values only when they differ. New native revert controls still receive their translated labels when constructed. Git reads, conflict checks, autosave scheduling and editor document handling are unchanged. No dependencies or Git caches were added.

## Local measurement

Windows x64, Obsidian 1.15.0, Electron 43.8.4, Chrome 150.0.7871.250, embedded Node v24.22.1, Git 2.50.0.windows.1. Builds use the same installed dependencies. One isolated repository has one base commit, no stashes, 100 Staged-only files and 100 Changed-only files. Other Git plugins are paused; the benchmark suppresses plugin background refresh, autosave, folding, highlighting and timing logging. The window and right editor are focused. Each target gets one discarded warm-up and five measured batches of 30 scripted insert transactions, after entering the dirty state. Scheduled rendering is allowed between batches outside the timer.

Sizes below describe the working fixtures before the insert batches. Each has one `value` replaced with `changed value`, adding eight bytes to the base fixture; raw samples include both sizes. The script alternates small Markdown, large JSON, small JSON and large Markdown, with deep directories and duplicate basenames. It observes toolbar/caption/warning/pane-label mutations, not editor-body mutations or physical repaint counts.

The reliable result is removal of redundant chrome writes in an already-dirty editor. Timings vary substantially, and the large Markdown median is slightly higher with overlapping ranges. Earlier runs without explicit focus also produced inconsistent timing directions; their raw synthetic samples are retained under `exploratory`. CPU sampling pointed at native editor/browser selection access, but it does not establish a single cause of the variance. No general typing-speed improvement is claimed. Startup, GUI click-to-diff latency, asynchronous layout completion, physical paint and memory improvements were not measured here. These values cannot establish a 50 ms navigation target.

## Reproduction and correctness

1. Use a disposable running vault named `note_test`, with no unsaved diff drafts. Pause other Git plugins.
2. Check out `1.0.0`, install dependencies and build from the repository root. Install the three files from `dist/vaultbranch` in the test vault and reload. Use the candidate's `tests/manual/editor-updates-ui.js` unchanged for both builds.
3. Evaluate that script in the Obsidian developer console or through `obsidian vault=note_test eval`. Keep the test window available. Save the returned JSON.
4. Build and reload `1.0.1`, then repeat with the same script. Do not run tests/builds concurrently with measurements.

The script creates/removes a temporary repository, restores plugin settings/repository state, verifies exactly 100 files in each status group, restores every draft after each batch, checks Staged read-only mode and unchanged index, and requires zero remaining editor sessions and zero captured runtime errors. It uses scripted CodeMirror dispatch, not trusted keyboard events.

`diff-view.test.cjs` adds a deterministic regression: 30 stable notifications must produce no chrome property/attribute writes, while saving/dirty transitions and zero/nonzero chunk navigation availability remain live. No wall-clock threshold is used in CI.

Local validation: all 108 existing automated tests passed, followed by the added regression (17 tests in its file). Obsidian checks passed: `diff-navigation-ui.js` (24), `chunk-revert-ui.js` (24) and `diff-loading-ui.js` (41), including live translations, undo, manual/autosave, locks, mixed file sizes, near/over-2-MB fallback, external-edit protection, latest-request handling and session cleanup.
