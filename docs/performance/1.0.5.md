## Behavior and implementation

SVG diffs default to decoded image previews in Changed, Staged, commit details and file history. A small icon at the right of the version-description row switches to source and back without increasing that row's height. Changed source edits the existing guarded draft session; Staged/history/deleted comparisons stay readonly. Switching preserves drafts, selection and native undo. The next preview uses the unsaved draft; toggling never saves or stages. Manual save and optional autosave retain their existing behavior. The source editor is created only on first use. Preview generation does not run on each source keystroke. No new dependency, framework or cache was added.

Previews use an image document, never inline SVG DOM. The actual Chromium UI test confirms embedded scripts are not executed and external image/HTTP requests are not made. Self-contained SVG is supported; externally linked resources are not loaded. Invalid SVG offers source repair. Existing UTF-8/path/conflict checks and the 2 MB text editing limit remain; larger files use the existing fallback. Image zoom/pan is reused. Canceled/closed reads release late images and editing sessions. A discovered raster-image failure race is also fixed: all parallel image reads settle before returning an error, so a status subprocess cannot outlive that failed request.

This is a feature release, with no speedup or 50 ms switching claim. The previous release had no SVG image preview, so its source editor is not an equivalent SVG-preview baseline.

CPU sampling, timing logging, highlighting, autosave and folding off. Input-to-document update, synchronous dispatch, delivery and following frame callbacks are recorded separately. ## Validation and reproduction

119 automated tests and 366 UI assertions pass in the final complete run. All existing image, editor, source-control, history, navigation and view-stability regressions pass. Index unchanged; final retained sessions, pending reads, captured runtime errors and console errors: zero.

The first automatic run exposed the parallel image-read/index-lock race described above. An intermediate benchmark batch overlapped an SVG-only CLI retry during initial setup; its timings are excluded in full and retained under excludedBatch in the raw file. The final complete run was performed alone against the exact source above. No fastest-sample selection.

1. Enable VaultBranch in a disposable note_test vault, save drafts and keep its window available for native input. Keep data.json unchanged when replacing assets.
2. Save official 1.0.4 main.js, manifest.json and styles.css into a baseline folder. Check out tested source d930dc70d9430b1e438cb7aca8a0ad041810f5c6 and install locked dependencies.
3. Run: npm run release:check -- --obsidian-cli <executable> --baseline-build <1.0.4 assets directory> --output-dir <local results directory>. This validates, tests, builds, compares both versions' startup/switch/input, and runs the entire UI suite including tests/manual/svg-preview-ui.js.
4. Review release-ui.json, logs, screenshots, timing samples and local CPU profiles. Only performance samples and synthetic checks are committed; screenshots/profiles remain local. Subsequent commits are release documentation only; the tag workflow adds the final release SHA.
