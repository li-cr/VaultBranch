# VaultBranch 1.0.3: module structure and release measurements

Baseline: [1.0.2](https://github.com/li-cr/VaultBranch/tree/1.0.2), commit c04b9ed. Tested source: [fda69df](https://github.com/li-cr/VaultBranch/commit/fda69dfd3d9b03484ab30f0b2b8e90edf78b2952). Release tag: [1.0.3](https://github.com/li-cr/VaultBranch/tree/1.0.3); [compare versions](https://github.com/li-cr/VaultBranch/compare/1.0.2...1.0.3). The release tag records the final commit; subsequent changes update documentation and append the release tag/SHA in the publishing workflow. Plugin runtime sources and the dependency lock remain the tested versions. Per-file SHA-256 values identify them in [raw samples](1.0.3-samples.json).

## Change and conclusion

EditorSessions owns per-file reads in flight, retained sessions, drafts, release rules and normal/hidden vault write adapters. The plugin supplies callbacks for the current Git service, settings and UI notifications. Autosave retains save scheduling and external-write protection; EditorDocument retains native document handling. Views call the session owner directly. Pure status/group/tree/patch/graph functions live in git-data.js and views import the needed functions directly. No dependency, worker, mutable Git cache or Git command change was introduced. GitService and the extracted pure function bodies were checked byte-for-byte against the baseline.

This is a responsibility/ownership refactor, with no demonstrated speedup. Timings vary with Git subprocess and filesystem wait. An initially slower candidate first-use batch did not reproduce in reversed-order tests: the baseline also became slower, and later candidate batches were faster. All batches are retained below rather than selecting the fastest run. This does not establish a 50 ms file-switch target. Full application cold startup, physical paint and memory improvements are not measured.

## Environment and method

Windows 10.0.19045 x64; Obsidian 1.15.0, Electron 43.8.4 / Chrome 150.0.7871.250, embedded Node v24.22.1, Git 2.50.0.windows.1. Local synthetic tests run only in the disposable note_test vault. Other Git plugin work is paused for each run; no benchmarks run alongside builds or test suites. Startup reloads have warm OS/V8 caches, openOnStartup=false and no workspace leaves; the sidebar is opened and refreshed explicitly. The live test vault has 8 tracked files, 6 commits and 4 stashes. First diff is an 80-line untracked fixture.

Switching/input use an isolated repository with exactly 100 Staged-only and 100 Changed-only files, including nested directories and duplicate basenames. Switching drives 48 trusted native GUI clicks, discards 8 warm-ups, and retains 20 measured clicks per area. CPU sampling and timing logging are on for both switching builds; their overhead is included. Autosave and syntax highlighting are off; folding uses the same restored setting in both builds. Git invocation medians are identical: Staged 5 calls, Changed 3 calls per navigation (ranges 4–5 and 2–3 respectively).

Input uses native trusted char/Enter/Backspace events, one warm-up plus five measured rounds per target and operation. CPU sampling, timing logging, highlighting, folding and autosave are off. It times event capture to CodeMirror document update, dispatch work, native event delivery and following frame callbacks separately. Restoring the document is outside the timers. Following-frame callbacks are scheduling observations, not physical paint; raw samples retain null for unobserved frames. Saving is outside these edit timers and covered by correctness regressions.

## Correctness and reproduction

115 automated tests pass. 226 Obsidian UI assertions pass across shared-editor, mixed-size loading, chunk revert, highlighting, startup/restore, diff navigation, sidebar selection, timing controls and image previews. Tests cover normal and hidden files, drafts and undo, readonly Staged, external changes, close-during-load, near/over-2-MB fallback and pending saves. Final test state has zero sessions, zero pending reads and zero captured runtime errors. Both switching and input probes assert an unchanged index.

1. Use a clean disposable note_test vault, save drafts, and build/install tag 1.0.2 from the repository root. Use this release's benchmark scripts for both builds; they accept both session layouts.
   For the complete pipeline in one invocation: npm run release:check -- --obsidian-cli <CLI executable> --baseline-build <1.0.2 assets directory> --output-dir <local results directory>. The following steps describe its constituent probes for investigation; release-check runs them sequentially and does not publish.
2. Evaluate scripts/benchmark-startup.js, save its JSON, and repeat by installing builds in candidate / baseline / baseline / candidate order. Each invocation performs one warm-up and five measured reloads. Preserve all batches and restore settings after each run.
3. Evaluate tests/manual/staged-switch-ui.js followed by tests/manual/profile-switch-ui.js. Save the returned samples and timing records; export window.__vbSwitchProfile locally if investigating CPU attribution, then delete that global. The driver cleans the isolated fixture.
4. Evaluate staged-switch-ui.js again, followed by tests/manual/edit-latency-ui.js. The latter returns 60 measured native edit records and restores drafts/settings/repository state. Run separately from profiling and builds.
5. Install tag 1.0.3, repeat with the same scripts/settings, and run npm run check, npm test, npm run build plus the UI scripts listed above. Preserve data.json when installing test builds. Do not install into the main user vault automatically.
