# VaultBranch

[English](README.md) | [简体中文](README_zh.md)

为 Obsidian 提供 Git 侧栏和提交历史图。

## 功能

- 查看文件改动、差异和提交历史。
- 右键查看文件历史，跟随 Git 识别的重命名，对比每次提交的修改。
- 创建、切换本地分支，也可从图中选中的提交创建分支。
- 直接在差异页右侧编辑并实时显示差异，按 Ctrl/Cmd+S 保存，也可开启自动保存。
- 在“其他”中开启“差异语法高亮”，仅支持 JSON 和 Markdown 源码，默认关闭。适用于可编辑差异、暂存区和文件历史，切换时保留草稿、选区和撤销。超过 20 万字符或单行超过 1 万字符时使用纯文本。Markdown 代码块使用统一代码样式，不解析代码块内部的语言。
- 使用两栏之间的箭头，从暂存版本恢复一个未暂存改动块；按 Ctrl/Cmd+Z 撤销。手动模式下先保留为草稿，自动保存遵循现有设置，不会自动暂存。暂存区和历史对比保持只读。
- 未修改内容默认折叠，可在其他设置中开关 CodeMirror 原生折叠。
- 使用 ↑ / ↓ 跳转差异，可在其他设置中控制按钮显示。
- 输入 `@date` 或用快捷键插入时间，在其他设置中配置格式。
- 在设置中切换中文 / English。
- 点击撤销箭头丢弃未暂存改动；未跟踪文件移入回收站。
- **Pull**：拉取远程改动。
- **Push**：推送本地提交。
- **Commit staged**：只提交暂存区的改动。
- **Stash push**：收起尚未提交的改动，留待之后恢复。
- **Stash pop**：恢复选中的 Stash，成功后删除该记录；发生冲突时保留记录。

仅支持桌面端，需要本机安装 Git。

## 安装与更新

- 如果 Obsidian 第三方插件目录中可以找到 VaultBranch，可在其中安装和更新。GitHub 发布成功不代表已通过目录审核。
- 使用 [BRAT](https://github.com/TfTHacker/obsidian42-brat) 添加 `li-cr/VaultBranch`，后续通过 BRAT 更新。
- 手动安装：从[最新发布](https://github.com/li-cr/VaultBranch/releases/latest)下载 `main.js`、`manifest.json`、`styles.css`，放入 `<笔记库>/.obsidian/plugins/vaultbranch/`，再在第三方插件设置中启用。手动更新时先停用插件，替换这三个文件后重新启用，保留 `data.json`。

笔记库需要是 Git 仓库。认证、提交身份、钩子和凭据助手遵循本机 Git 配置。VaultBranch 会读取仓库文件和 Git 元数据，并调用本机 Git，使用与 Obsidian 相同的系统权限。

## 编辑与保存

默认手动保存。右侧编辑和块级回退先保留为草稿，保存后才写入工作文件。可选的自动保存在停止输入 500 ms 后，以及切换文件或执行 Git 操作前保存。保存与暂存是两个独立操作，提交只包含已有暂存区。未保存草稿会阻止 Git 操作，外部修改与草稿冲突时暂停覆盖。暂存区和历史对比保持只读。

## 调优记录

在“设置 → VaultBranch → 其他”开启“调优：记录操作耗时”，设定“调优记录条数”，点击侧栏文件，再打开“查看记录”。

- 在纯文本编辑器中选择、编辑和复制报告；复制按钮复制当前显示的文本。编辑报告不会修改原始测量记录，清空会删除内存中的记录。
- 默认关闭，默认保留最近 100 条；设为 0 则保留本次运行的全部记录。调低条数会立即移除较早的记录。
- 包含相对文件路径和各阶段耗时，不含文件正文，不自动上传。只保存在内存，关闭记录或重新加载插件时清空。
- 内容就绪、导航完成、动画帧回调是不同指标。各阶段可能重叠，不能直接相加；动画帧回调不保证屏幕已经完成绘制。记录本身也有开销。

## 当前性能与 50 ms 目标

0.2.32 的本地 Windows 实机测试中，关闭调优记录、缓存预热后，从真实鼠标点击到完整页面 DOM 就绪，小 Markdown 的中位数为 **103.2 ms**，小 JSON 为 **100.2 ms**；0.2.31 对应为 131.3 和 146.5 ms。大 JSON 和大 Markdown 为 133.6 和 115.2 ms。每项各测五次，仅代表本地测试，不保证所有机器的延迟或实际屏幕绘制时间。详见[测试条件、范围、原始数据与复现方法](docs/performance/0.2.32.md)。

**50 ms 是常用文件切换的目标，目前尚未达到。** 下一步拟减少索引未变化时反复启动 Git 的等待：实时读取索引字节，只有与缓存对应字节完全一致时，才复用 Git 已解析的条目；工作文件仍实时读取，Git 原文按不可变哈希复用。索引变化或缓存未命中时仍需调用 Git。实现前需要验证 linked worktree、替代索引、split index 和同时暂存等情况，不能只凭缓存有效期或文件修改时间判断。

首次打开、缓存未命中和大文件单独测量。保留草稿、保存顺序、全局冲突检查和外部修改保护；使用真实侧栏点击、大小 JSON/Markdown 交错、多级目录，分别验证调优记录开启和关闭时的表现。本次 0.2.33 仅更新文档，没有新增运行时优化或性能测量。
