# Obsidian UI checks

Build and install VaultBranch into a disposable Obsidian vault named `note_test`. Enable the plugin, open the developer console, and paste one script at a time. Each script returns its passed assertions and captured runtime errors. Do not run scripts concurrently.

- `file-history-ui.js`: creates an isolated temporary Git repository and temporarily points the plugin at it. Checks Git graph nodes, stable row heights, fork lanes, 50-entry pagination, renamed files, branch scope, read-only comparisons, native collapse/expand, keyboard selection, rapid requests, sidebar context menu, index preservation and editor cleanup. Waits for asynchronous navigation completion with bounded polling. Restores the plugin's repository afterward.
- `view-stability-ui.js`: uses an isolated temporary repository to gate file-history, graph and conflict reads. Checks complete-page retention, synchronized selection/details, 250-row detached graph batching, busy-only sidebar node reuse, errors, unchanged-data refreshes, draft preservation, index preservation and late results after closing. The 250-row case repeats real commit metadata to exercise batching; it is not a large-repository latency benchmark.
- `history-stability-fixture.js`: used by `node scripts/check-history-stability.cjs <test-CDP-port>` for 12 trusted mouse clicks alternating small/large JSON historical versions. Checks that no loading placeholder or mismatched title appears. Restores repository state and removes its temporary repository afterward. See `docs/performance/view-stability.md` for baseline/candidate results. Neither script claims lower Git latency.
- `history-editor-ui.js`: creates one temporary note in `note_test` and stages only that file. Checks editable draft/selection/undo preservation and native editor/file-explorer menus. Removes that index entry, trashes its note and restores preferences afterward.
- `diff-navigation-ui.js`: checks previous/next native chunk navigation, deletion chunks, wraparound, live button availability, translated labels, settings persistence and draft/undo/index preservation. Uses one disposable test note and an isolated temporary history repository; restores preferences and removes test data afterward.
- `startup-ui.js`: reloads the plugin with a closed workspace, then restores all five view types through native leaf state. Checks deferred loading, serialized manual drafts, editor access modes and cleanup. Creates and trashes one temporary note without staging it; restores preferences afterward.
- `background-refresh-ui.js`: checks closed/collapsed/inactive sidebars, polling, refreshing when revealed, explicit refresh and editor external-change protection. Creates and trashes one temporary untracked note and restores preferences afterward. Required editor conflict safety reads remain enabled even when sidebar refreshes are suspended.
- `chunk-revert-ui.js`: checks native index-to-working-copy chunk reverts, mouse and keyboard-equivalent activation, deletion/insertion blocks, manual save, autosave, undo, Git locks, translated labels, readonly comparisons and untracked drafts. Stages only its temporary fixture in note_test, removes that index entry and trashes the fixtures afterward.
- `syntax-highlight-ui.js`: checks the native default-off setting, JSON/Markdown source colors, both panes, live toggles, draft/selection/undo preservation, staged readonly content, diff backgrounds, unsupported extensions, size limits and edit/undo limit transitions, hidden JSON autosave and cleanup. Stages only its disposable JSON fixture and restores settings afterward.
- `syntax-history-ui.js`: uses an isolated temporary Git repository for readonly JSON history and a Markdown-to-text rename. Checks historical extension selection, live settings, index preservation and cleanup, then restores the original repository.
- `sidebar-selection-ui.js`: checks row/button reuse, staged/unstaged duplicates, special paths, conflict routing, keyboard-equivalent activation, unchanged refreshes, folder collapse, status additions/deletions, staging transitions and busy controls. Uses synthetic status for these cases, then disposable real Markdown files for A/B navigation, draft retention, line/diff updates, new-input undo and unchanged index. Restores methods/settings, removes its temporary index entry and trashes its fixtures.
- `diff-loading-ui.js`: checks complete first-open and switching UI, blocked interaction while pending, background refresh, rapid clicks, failures and close-during-load cleanup. Alternates real small Markdown, 1.6 MB JSON, small JSON and 1.2 MB Markdown across nested directories and duplicate basenames; also checks editable near-2-MB JSON and over-2-MB patch fallback. Covers drafts, live line counts, new-input undo, manual save, readonly staged comparisons, external edits and unchanged index. Restores methods/settings and removes its temporary index entries and fixture folder.
- `editor-updates-ui.js`: measures 30 scripted insert transactions per batch in a focused editable pane, with one warm-up and five measured batches for mixed small/large Markdown/JSON targets. Counts redundant toolbar/caption/warning/ARIA mutations separately from editor-body changes. Uses an isolated 100-Staged/100-Changed repository and checks unchanged index, readonly Staged and session cleanup. Run separately from builds/tests; see `docs/performance/1.0.1.md` for timing limits and raw samples.
- Set `window.__vbEditorProbe = { materialize: true, cpu: true }` before evaluating `editor-updates-ui.js` to count large-document `toString` calls and collect a V8 CPU profile in `window.__vbEditorProfile`. For trusted native input, use `{ nativeInput: true }` instead; its batch times include event scheduling and rendering, and are not per-key latency. Delete these globals afterwards. See `docs/performance/1.0.2.md` for matched baseline/candidate samples.
- `shared-editor-ui.js`: checks two diff views sharing one native document session, input in either view, JSON workspace snapshots, manual-save isolation, final save and session cleanup. Creates and trashes one untracked fixture and restores its preference.
- `profile-switch-ui.js`: evaluate after `staged-switch-ui.js`. Focuses the test window and drives 48 native trusted mouse clicks across Staged/Changed mixed-size files, discarding eight warm-up clicks. Returns per-stage records and saves the CPU profile in `window.__vbSwitchProfile`; restores the repository and removes the isolated fixture. Delete the profile global afterwards. This is the Electron-native alternative when no remote CDP port is available; profile timings include sampling overhead.
- `edit-latency-ui.js`: evaluate after `staged-switch-ui.js`. Measures trusted native text insertion, Enter and Backspace in the four mixed-size Changed targets, with one warm-up and five measured rounds per operation. Separates event-to-document time, synchronous dispatch and a following animation-frame callback; does not claim physical paint. Restores each draft outside the timers, checks the unchanged index and session cleanup, and removes the fixture. Run with CPU sampling, timing logging, highlighting, folding and autosave off, separately from builds/tests.
- `performance-timing-ui.js`: checks disabled/enabled timing, persistence, separate DOM-ready/completion milestones, live Git/editor/verification spans, readonly comparisons, errors, the report viewer, copy/clear actions and disabling during a pending load. Verifies records contain no fixture body and do not enter saved workspace drafts or preferences. Mocks clipboard writes to preserve the real clipboard; restores methods/settings and removes its disposable files/index entry.

All scripts refuse to run in a vault with a different name. They require a working Git executable and the normal file explorer enabled. Use a clean test session with no existing unsaved diff drafts. The normal `npm test` suite does not require Obsidian.

For repeatable plugin reload and first-use measurements, run `scripts/benchmark-startup.js` separately. See `docs/performance/0.2.21.md` for the baseline, environment, sample results and limitations.

For background Git subprocess counts, run `scripts/benchmark-background-refresh.js` separately. See `docs/performance/0.2.22.md`; it temporarily closes sidebar leaves and restores the startup, refresh and collapse preferences.

For JSON/Markdown highlighting overhead, run `scripts/benchmark-highlighting.js` separately. It alternates off/on modes for five measured opens and thirty insert transactions per sample using synthetic files, then restores settings and trashes its files. See `docs/performance/0.2.24.md` for measurements and limitations. Do not run timing benchmarks alongside tests or builds.

For file selection costs in the sidebar, run `scripts/benchmark-sidebar-selection.js` separately on each build. It renders synthetic 10/100/1000-file statuses and records five click/layout batches after one warm-up. The actual file-row handlers run, but opening the diff is replaced by a recorder, so results isolate sidebar selection rather than total file navigation. It counts reused DOM nodes and Git calls, then restores the original methods/state. See `docs/performance/0.2.27.md`.

For actual mixed-size file switching and intermediate UI states, run `scripts/benchmark-diff-switch.js` separately on each build. It uses real staged/modified files in nested directories, alternates small Markdown → large JSON → small JSON → large Markdown, discards one warm-up cycle and records five measured cycles. MutationObserver and animation-frame sampling record partial/blank pages and header height; timings include Git reads and editor loading plus a bounded two-frame wait, without guaranteeing display paint completion. See `docs/performance/0.2.28.md`. Do not run timing benchmarks alongside tests or builds.

For trusted GUI mouse clicks and per-stage profiling, use `node scripts/benchmark-gui-diff.cjs <test-CDP-port> off` and repeat with `on`. The driver loads `gui-timing-fixture.js` into the independent `note_test` window, sends mouse press/release events through CDP Input, verifies `isTrusted`, discards one warm-up cycle and collects five cycles across small Markdown / large JSON / small JSON / large Markdown in nested directories. It separates DOM-ready, frame callbacks and navigation completion; polling waits are outside these timestamps. It temporarily wraps methods for baseline attribution and captures the candidate's optional records, then restores state and trashes fixtures. Run it separately from builds/tests. See `docs/performance/0.2.29.md`.

For file-history graph data overhead, run `node scripts/benchmark-file-history-graph.cjs` separately. It compares five alternating graph-on/off reads after warm-up for a 50-commit page in synthetic 1,000-change linear and interleaved histories. It reports Git commands and data-loading time only, not Obsidian rendering or paint. It creates/removes its own temporary repository. See `docs/performance/file-history-graph-samples.json`.

For Staged vs Changed GUI switching, run `node scripts/benchmark-staged-switch.cjs <test-CDP-port>` separately. It creates an isolated repository with 100 staged and 100 unstaged files, sends trusted mouse clicks for small Markdown, large JSON, small JSON and large Markdown in each group, discards one eight-click warm-up round and records five clicks per mode/file. It checks staged read-only mode, Changed editability and unchanged index, then restores settings and removes the temporary repository. Timings stop at navigation completion and do not claim physical paint. See `docs/performance/0.2.36.md`.

For image comparisons, evaluate `image-preview-ui.js` in the disposable `note_test` vault. It creates an isolated Git repository, tests PNG/JPEG/WebP/GIF decoding, alternating small and 3.4-MiB nested images, Changes vs Staged vs commit/file-history content, root/deleted versions, corrupt/oversized files, late requests and resource cleanup. It checks that the index stays unchanged and restores the original repository. Run `diff-loading-ui.js` afterwards for the mixed Markdown/JSON editing regression; pause other Git plugins during that test to avoid index-lock contention.

The image script also focuses the test window and uses Electron native mouse input to check trusted wheel zoom, dragging and pointer release, alongside initial-fit/eight-times bounds, independent panes, stable layout and double-click reset. Keep the test window available while these checks run.
